# 프론트 언어 선택 기준

**1. 기술별 상세 역할 및 선택 이유
Next.js (App Router)**
• **역할:** React를 기반으로 한 **풀스택 프레임워크**입니다. 브라우저에서 실행되는 클라이언트 사이드 렌더링(CSR)뿐만 아니라, 서버에서 미리 화면을 그려주는 서버 사이드 렌더링(SSR) 및 정적 사이트 생성(SSG)을 관리합니다.
• **선택 이유:** * **SEO 최적화:** 서버에서 HTML을 미리 생성하므로 검색 엔진 노출에 유리합니다.
    ◦ **성능:** 필요한 데이터만 서버에서 가져오는 '서버 컴포넌트' 기능을 통해 초기 로딩 속도를 획기적으로 줄일 수 있습니다.
    ◦ **편의성:** 이미지 최적화, 폰트 최적화, 자동 라우팅 등 웹 서비스 구축에 필요한 기능을 기본으로 제공합니다.

**React**
• **역할:** UI를 독립적인 **컴포넌트(Component) 단위**로 나누어 개발할 수 있게 해주는 라이브러리입니다. 데이터(State)가 변하면 화면의 바뀐 부분만 효율적으로 다시 그려줍니다.
• **선택 이유:** * **선언적 UI:** 화면이 어떻게 보일지 코드로 선언하면 데이터에 맞춰 알아서 업데이트되므로 복잡한 UI 관리가 쉽습니다.
    ◦ **생태계:** 가장 큰 커뮤니티와 수많은 외부 라이브러리를 보유하고 있어 문제 해결이 빠릅니다.

**TypeScript**
• **역할:** 자바스크립트에 **타입(Type)** 시스템을 추가한 언어입니다. 변수나 함수의 입출력 값이 숫자형인지, 문자형인지 등을 명확히 규정합니다.
• **선택 이유:** * **런타임 에러 방지:** 코드를 실행하기 전(컴파일 단계)에 오타나 데이터 타입 불일치 등의 에러를 미리 잡아내어 서비스의 안정성을 높입니다.
    ◦ **자동 완성:** 에디터에서 데이터 구조를 미리 알 수 있어 코딩 속도가 빨라지고 협업이 원활해집니다.
